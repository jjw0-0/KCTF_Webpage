# 문제 보드 UI 결정 기록

문제 카드와 상세 화면의 시각 효과를 바꿀 때에도 접근성과 탐색 동작을 유지하기 위한 기록입니다. 실제 화면 용어인 **Author**, **PTS**, **SOLVERS**, **INSTANCE**는 그대로 사용합니다.

## 상태 알림과 진행도

이전에는 문제 목록 전체에 `aria-live`가 있어 필터 변경이나 풀이 완료 때 여러 노드가 바뀌면 화면 읽기 도구가 목록을 길게 다시 읽을 수 있었습니다. `polite`는 알림을 없애는 설정이 아니라 읽기 적절한 순간까지 기다리는 설정입니다. 지금은 “PWN 문제 1개 표시”처럼 짧은 `role="status"`만 필터 결과를 알리고, 플래그 제출 결과는 상세 화면 안의 별도 상태로 알립니다.

화면에 보이는 `전체 n / m 해결`은 현재 필터와 관계없이 공개된 전체 문제 중 해결한 수입니다. 필터 결과의 문제 수는 별도로 알립니다. 두 수치를 같은 의미로 바꾸지 마세요.

## 상세 화면과 탐색

카드의 겹침과 움직임은 CSS 3D transform으로 구현하고, 카드에서 상세 화면으로 이어지는 동작은 지원 브라우저의 View Transition API를 사용합니다. 카드마다 별도 WebGL 장면을 만들지 않습니다. 두 겹의 면과 가장자리 조명으로 깊이를 표현하며, 회로 무늬 같은 장식은 내용의 위계를 방해하지 않도록 제거했습니다.

상세 화면은 최대 740px 너비의 **1열**로 고정합니다. 기존 `modalLayout` 파라미터로 2열을 복원할 수 없습니다. 데스크톱은 680px, 모바일은 최대 720px 높이를 사용하되 작은 화면에서는 뷰포트 안으로 줄어듭니다. 설명·인스턴스·플래그 제출은 하나의 스크롤 영역으로 이어지고, 설명과 작업 영역은 콘텐츠 종류가 달라도 같은 외곽 크기와 가로 기준선을 유지합니다. 설명이 아래에 남았을 때만 모달 하단 중앙에 스크롤 안내를 표시하고, 설명 끝이 보이면 사라집니다. 모바일 제목 오른쪽에는 닫기 버튼만 두고 점수는 작성자와 같은 줄에 배치합니다.

밝은 테마의 내비게이션은 흰색이며 로고 원본 색상을 유지합니다. 관리자 입력창·선택지·로그는 공통 표면/텍스트 토큰을 사용합니다. 테마 전환 후 애니메이션이 끝난 상태에서 밝음→어두움→밝음의 대비를 확인합니다. 공개 프로필 링크는 `/users/{username}`을 사용하며 같은 경로에서 기존 ID 링크도 유지합니다.

참고한 [Lucas의 레퍼런스 모음](https://x.com/lucass0x/status/2122800357965213986)은 공간 구성과 절제된 깊이 표현에, [Benjamin의 UI 스킬 모음](https://x.com/benjaminuix/status/2122286309855338953)은 일관된 간격과 작은 상호작용 검토에 활용했습니다. 특정 영상의 장식을 그대로 복제하거나 스킬 개수를 늘리는 것을 품질 기준으로 삼지 않습니다.

설명 이미지의 원본 크기를 아는 경우 Markdown 제목에 `![설명](https://example.com/image.png "800x600")`처럼 너비와 높이를 적습니다. 유효한 크기 쌍은 이미지 영역을 미리 확보해 로딩 중 레이아웃 이동을 줄입니다. 크기를 모르면 일반 Markdown 이미지를 사용하며 정확한 화면 비율은 미리 확보할 수 없습니다.

카테고리 탭과 닫기 버튼의 터치 높이는 최소 44px입니다. 짧은 화면에서는 상세 화면 전체를 스크롤할 수 있습니다. 하이드레이션이 끝나기 전에는 카테고리·카드·빈 상태 버튼을 잠시 비활성화해 클릭이 아무 반응 없이 사라지지 않게 합니다.

카테고리와 선택한 문제는 URL에 반영됩니다. 카드를 열면 브라우저 기록이 추가되어 뒤로 가기로 닫고 앞으로 가기로 다시 열 수 있습니다. 직접 연 문제 링크는 닫을 때 URL을 교체하여 보드에 남습니다. Escape와 닫기 버튼으로 닫을 수 있고, 열려 있는 동안 초점은 상세 화면 안에 머뭅니다. 닫은 뒤에는 가능하면 원래 카드로 초점을 돌립니다.

`prefers-reduced-motion: reduce`에서는 JavaScript가 View Transition API 실행 자체를 건너뛰고 CSS 카드 움직임도 제거합니다. 애니메이션 없이 같은 내용과 키보드 기능을 사용할 수 있어야 합니다. 변경 시 좁은 모바일 화면, 밝은 테마, 긴 설명, 키보드 초점, 빠른 열기·닫기를 확인하세요.

## 글자 크기와 입력 컨트롤

글자 크기는 `rem`을 사용해 브라우저의 기본 글자 크기 설정을 따릅니다. 카드의 내용 영역도 함께 커지며, 좁은 화면에서는 헤더 메뉴와 푸터 링크가 줄바꿈됩니다. 기본 글자 크기에서는 기존 크기와 배치를 유지합니다. 변경 시 200% 글자 확대에서 카드 제목과 플래그 입력을 확인하세요.

스크롤바를 전역으로 숨기지 않습니다. 관리자 표와 로그, 문제 목록은 기본 스크롤바를 유지하고, 상세 설명은 좁은 스크롤바를 사용합니다. 강제 색상 모드에서는 시스템 색상과 기본 너비를 따릅니다. Dynamic flag는 기본 체크박스와 `accent-color`로 표시하며, 키보드 초점도 유지합니다.

선택 메뉴는 방향키·Home·End·문자 검색으로 옵션을 탐색하고 Enter 또는 Space로 선택합니다. Tab과 Shift+Tab은 값을 바꾸지 않고 다음·이전 컨트롤로 이동하며 메뉴를 닫습니다. Escape는 원래 버튼으로 초점을 돌리고, 메뉴 밖으로 초점이 이동해도 닫힙니다. 긴 옵션 목록은 내부에서 스크롤됩니다.

이 동작은 `tests/e2e/accessibility.spec.ts`에서 Chromium, Firefox, WebKit으로 확인합니다. WebKit은 강제 색상 에뮬레이션을 제외하고 기본 체크박스를 검사합니다. Headless Firefox는 스크롤바 표시를 강제로 숨기므로 해당 환경에서는 스크롤 동작을 검사하고, 표시 상태는 창이 있는 브라우저에서도 확인해야 합니다.

## 보류한 확인 절차

참가자의 `종료`와 `현재 Instance 교체`는 현재 별도 확인창 없이 실행됩니다. 실행 중인 문제 VM의 작업 내용이 사라질 수 있으므로, 어느 인스턴스에 어떤 영향이 생기는지 보여 주는 동작별 확인창은 추후 구현 대상으로 남겨 두었습니다.
